# 产品定义

## 用户问题

招聘岗位分散在多家招聘官网；投递后进度难以集中追踪；重复搜索、漏跟进和把“已确认想投”误记成“已投递”都会让记录失真。

## 目标流程

公开岗位检索 → 按地点、招聘类型和目标岗位／关键词筛选 → 展示来源与缺失字段 → 用户逐岗确认 → 匹配简历版本 → 执行官网投递 → 验证提交结果 → 记录状态 → 同步飞书。

现有版本支持自定义筛选和公司管理，并通过 Codex 桌面定时任务和浏览器代理检查真实官网；服务端负责周期判断、去重、运行日志和完成核验。支持固定简历版本和经用户逐岗授权的 Codex 投递任务；内置无头采集器、逐站真实表单验收仍未完成。自动更新运行条件见 AUTOMATION.md。

## 数据准则

- 查询岗位与读取个人投递是两种权限和两套连接状态。
- 未投过的公司只查询公开岗位，不要求登录来证明没有投递。
- 仅确认明确的工作地点和招聘类型；未知项保留待核对。
- 已投事实与投递日期分开：可以知道已经投递，却不知道具体日期。
- 日期只有年月日时按原精度保存，不补成当天 00:00。
- 官网原文始终保留；归类只是展示用途，不覆盖原文。
- 部分分页读取必须标记 partial，不得宣称读完全部记录。
- 一个失败来源不覆盖另一来源；同名职位不必然是同一岗位。

## MVP 验收

- 首次克隆后能初始化空数据库并打开页面。
- 同一来源记录重复导入不重复创建，用户决定不会被刷新覆盖。
- 登录失败不会把筛选中变成已结束。
- 不符合地点或招聘类型的岗位不能被正常批准进入投递队列。
- 确认后仍显示待投递，直到有真实投递事实。
- 飞书同步失败有明确结果，既有记录不丢失。

## 非目标

不批量海投，不绕过验证码或站点访问限制，不生成虚假经历，不通过职位名称猜测录用结果。
