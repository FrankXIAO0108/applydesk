# Vibe Coding 开发提示词

以下提示词用于继续开发，不是已经完成的功能声明。

## 1. 理清需求

“阅读 README、PRODUCT 和现有代码。先列出现有行为与未实现行为，一次只问一个影响设计的问题。不要猜测登录状态、投递结果或简历内容。把确认后的验收条件写进任务说明。”

## 2. 增加一个官网适配器

“仅接入一个指定官网。使用用户授权的浏览器会话读取可见页面，核实岗位链接、招聘类型、地点、分页与投递状态。先做只读路径，再通过既有 API 写入。覆盖登录失效、空结果、部分读取和重复记录。不要读取浏览器 Cookie 文件，不绕过站点安全限制。”

## 3. 实现定时巡检

“先确认浏览器会话如何被后台任务获取，以及电脑休眠、断网、节假日和重复触发如何处理。用单一执行器调度现有适配器；失败不能改写已知投递状态。保存每次运行结果并展示最后成功时间。以真实运行验证调度，不要仅把界面状态改成 enabled。”

## 4. 实现简历匹配与投递

“为简历版本建立显式映射，显示拟投岗位、版本与必要表单字段。只有用户对具体岗位确认后才能进入执行流程。提交前检查字段，提交后从官网结果验证；不确定时停止并标为需人工处理。禁止重复提交。”

## 5. 对抗式审阅

“逐项查找：确认意愿是否被当作已投；登录失败是否被当作拒绝；日期是否被编造；列表 URL 是否合并不同职位；新抓取是否覆盖用户忽略决定；错误公司是否能借用共享招聘平台域名；私密数据是否进入仓库；生产身份能否伪造。修复可复现的问题，再运行相关测试。”

## 开发节奏

冻结一个小需求 → 实现一个完整路径 → 检查真实输出 → 修复失败分支 → 更新功能状态。不要为了一个漂亮演示，把尚未运行的功能写成已上线。
