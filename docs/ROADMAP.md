# 路线图

## v0.4：通用岗位与两种投递入口

- [x] 自定义岗位名称／关键词，移除算法岗位限制，逐官网输出检索清单。
- [x] 日常／暑期实习、秋招、春招、全部校招、社招等招聘类型。
- [x] Chrome／Edge 浏览器偏好。
- [x] 官网自行投递入口；打开链接不等于已投。
- [x] 本地简历版本、明确授权、Codex 投递任务、重复拦截与回执证据。
- [ ] 各招聘网站真实表单的逐站验收；当前不宣称全部网站自动投递成功。

## v0.3：面向其他使用者

- [x] Codex 对话作为主入口，按对话增改官网和筛选条件。
- [x] 一条启动命令、空目录安装、端口避让与实例校验。
- [x] 无个人投递假设的初始配置、可选网页向导。
- [x] 不依赖 WebMCP 的本地数据 CLI，仍通过浏览器读取官网。
- [x] 指定公司立即检查、自动暂停与手动操作分离。
- [x] Windows / Linux 首次使用 CI。

## v0.1：可验证的记录与决策 MVP

- [x] 看板、持久化、公司范围、候选筛选。
- [x] 人工确认队列、官网原文、异常留痕。
- [x] 飞书同步与代理数据入口。
- [x] 本地启动、空数据库、隐私导出检查、基础测试。

## 下一步：让一次真实巡检可重复运行

- [ ] 一个官网的独立只读适配器与合成测试夹具。
- [ ] 登录、分页、记录标识和失败恢复的明确契约。
- [ ] 首次观察和后续变化的完整审计证据。

## 再下一步：调度与可运维性

- [x] Codex 桌面定时任务执行协议、北京时间周期、重复触发控制。
- [x] 自定义筛选、公司管理、每周／两周检索周期。
- [x] 运行历史、服务端核验、超时与部分完成记录。
- [ ] 不依赖桌面代理的独立采集器与云端调度。
- [ ] 公开部署所需的身份认证和秘密管理。

## 最后：受控投递

- [x] 多版本简历选择；缺失信息时暂停等待用户。
- [x] 逐岗确认、提交前核验、提交后回执和重复提交拦截。
- [x] 验证失败转待处理或待核实，保存中间状态。

不以“有按钮”“保存了设置”或“模型说成功”作为完成标准。
